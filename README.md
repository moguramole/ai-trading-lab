# AIトレード研究所（仮想売買のみ）

GPTとClaudeの売買判断を、同じ条件の仮想口座（各30万円）で比較する研究アプリ。
**実注文・証券口座ログイン・自動発注の機能は存在しない。** APIも呼ばない（費用0円の手動運用）。

## 起動

```powershell
.\.venv\Scripts\Activate.ps1
streamlit run app.py
```

初回のみ: `python -m venv .venv` → `pip install -r requirements.txt`

## ポータル（状況の確認）

**PCにログインすると自動で起動する**（タスクスケジューラ `AI-Trading-Lab-Portal`、ログオンの30秒後、非表示）。ブラウザで http://localhost:8501 を開くだけ。
`start_portal.bat` をダブルクリックしても開ける（すでに動いていれば二重起動はしない）。起動ログは `data/portal.log`。
停止: `Stop-ScheduledTask AI-Trading-Lab-Portal; Get-Process streamlit | Stop-Process`／自動起動をやめる: `Unregister-ScheduledTask AI-Trading-Lab-Portal`
データはすべてローカル。状況タブ・成績・ログは30秒ごとに自動更新される。

| タブ | 内容 |
| --- | --- |
| 状況 | データの鮮度、直近の取得結果、次回の自動取得、AI判断待ちの有無、最新株価 |
| 市場全体 | 日経平均・TOPIX、上昇銘柄の割合、業種別の動き、上昇/下落上位、AIに見せる候補 |
| 成績比較 | GPT / Claude / AIなしの資産推移（日経平均・TOPIX・全銘柄保有の線つき）、最大ドローダウン、勝率 |
| 過去検証 | AIなしのルール戦略の約1年分のバックテスト。ボタンで実行（約20秒）。前半/後半の分割、ランダム対照つき |
| 口座詳細 | 現金・保有銘柄・取引履歴・拒否された注文 |
| AIへの依頼・登録 | 依頼文（最新データ入り）を生成。回答JSONを貼って登録（DBに保存） |
| 更新ログ・ルール | 取得ログ、対象銘柄、固定ルール |

### 持ち株（個人の保有）

「持ち株」タブに、自分の持ち株（銘柄・株数・平均取得単価）を登録すると、終値ベースの評価額・評価損益・構成比・業種の偏りを表示する。
**仮想売買とは完全に別**で、AIの判断・仮想口座・リスク判定には使わず、注文機能もない。データは `data/lab.db` の `holdings` テーブルにだけ保存（Git管理外・外部送信なし）。
TOPIX500外の銘柄も登録でき、価格は自動取得の対象に加わる（仮想売買の対象には入らない）。評価は証券会社の画面と一致しない（配当・手数料・税金は含まない）。
バックアップは `data/lab.db` をコピーする。

### 見た目の方針（`src/ui.py`、`.streamlit/config.toml`）

- 日本の相場の慣習に合わせ、上昇は朱、下落は藍。
- 正常は色を付けず、異常（遅れ・要確認・判断待ち）だけに色と記号（▲■）を付ける。色だけに頼らず言葉も添える。
- 箱（カード）を並べず、罫線と余白で区切る。グラフは凡例をやめ、線の右端に名前と値を直接書く。
- 書体はBIZ UDPGothic（UD書体）。Google Fontsから読み込むため、オフラインでは代替フォントになる。
- デザインの判断には Anthropic 公式の `frontend-design` スキル（`.claude/skills/frontend-design/`）の指針を使った。

## 使い方（手動運用）

1. 「AIへの依頼・登録」タブで宛先（gpt/claude）を選び、依頼文をコピーしてそれぞれに貼る。
   依頼文には市場全体の要約、業種別の動き、ルールで絞った候補銘柄（約20）、そのモデルの口座状況が入る。
   候補は全銘柄から機械的に絞るため、絞り込み自体が結果に影響する点に注意（理由は reason 列）。
2. 返ってきたJSON配列を同タブに貼って登録。不正なJSONは登録されず見送りになる。
3. 翌営業日の始値で仮想約定され、成績に反映される。

判断JSONの形式は `sample/example_signal.json` を参照。

判断JSONの形式は `sample/example_signal.json` を参照。項目:
`model, as_of, ticker, action(buy/sell/hold), confidence(0〜1・確率ではない), reason, risk_notes, qty, stop_price(任意)`

## スマホで見る・PCオフで更新（GitHub Actions）

`.github/workflows/daily.yml` が平日21:30（JST）にクラウド側で株価取得→仮想約定・集計→スマホ向けページ（`src/site.py`）を更新する。
- DBは持ち株を除いたもの（`src/publicdb.py`）を `data` ブランチに1コミットだけ置く。ページは `gh-pages` ブランチ。
- 載せるのは仮想売買の成績・判断・取引と市場概況だけ。**持ち株は載せない・クラウドに上げない。**
- 判断JSONは `answers/answer_<gpt|claude>_<判断日>.json` を push すると登録される（検証はPCと同じ。締め切り・1日1回も同じ）。
- クラウドで動かす間は、PC側の `AI-Trading-Lab-DailyUpdate` タスクは止める（DBが二重に更新されるため）。

## 株価の自動取得（毎日）

- 取得元: yfinance（Yahoo Finance、非公式）。**個人の研究用途のみ**。仕様変更で止まる可能性あり。差し替えは `src/fetch.py` のみ。
- 対象銘柄: **JPX公式の上場銘柄一覧から TOPIX500（Core30 + Large70 + Mid400、約490銘柄）** を自動選定（週1回更新）＋市場指標（日経平均 `^N225`、TOPIX連動ETF `1306`。売買対象外）。一覧が取れず保存分もないときのみ `watchlist.txt` を使用。
- 取得失敗が全体の5%を超えると終了コード1（数銘柄の欠損は許容し、ログに残す）。
- 手動実行: `python -m src.update --period 1mo`（初回は `1y` など長め）。
- 定時実行: タスクスケジューラ `AI-Trading-Lab-DailyUpdate`（平日21:30。PCがoffなら起動後に実行、失敗時は10分間隔で3回再試行）。
- 確定前の当日分（15:45前）は保存しない。検証に落ちたデータは保存せず、他銘柄は続行。再実行しても重複しない。
- 結果は `data/update.log`。失敗があると終了コード1。
- 画面は、SQLiteにデータがあればそれを表示（なければ架空サンプル）。
- 停止する場合: `Unregister-ScheduledTask -TaskName AI-Trading-Lab-DailyUpdate`

## 価格データの自動補正

Yahoo Financeのデータには、分割の未調整・一時的な異常値・無効な価格が混じることがある（実例: 1306で2日間だけ価格が約1/10、8227の3分割が未反映、8303の再上場前に巨大価格）。
読み込み時（`data.clean`）に、①日本株にあり得ない価格の除去 ②数行で元に戻る異常値の除去 ③整数倍に近い水準のずれは分割・併合として過去分を調整 ④原因不明のずれは銘柄ごと除外、を行う。
元のDBは書き換えず、処理内容は「更新ログ・ルール」タブと更新ログに出る。

## 過去検証（バックテスト）

`python -m src.backtest` または「過去検証」タブ。ルール（sma_cross / pullback / momentum / random）は事前に固定し、結果を見ての調整はしない。
判断は当日終値までの指標のみ（未来情報なしをテストで確認）、約定は翌営業日の始値、手数料・スリッページ・資金制限は本番と同じ。
**注意**: 約1年・1つの相場、銘柄は現在のTOPIX500（生存者バイアス）、戦略ごとに投入資金が違う。優劣の根拠にはならない。

## 候補ルールの見直し（2026-10-28）

AIに見せる候補の絞り込みを、過去検証（`python -m src.backtest --variants`）で見直した。**結果を見る前に決めた6案だけ**を比べ、前半（調整期）と後半（未知）で一貫しない案は採用しない方針。

| ルール | 総リターン | 最大DD | 前半 | 後半 |
| --- | --- | --- | --- | --- |
| pullback（旧） | +11.7% | -27.2% | +22.9% | -17.4% |
| **pullback_mkt（採用）** | +12.4% | -14.3% | +13.7% | -2.5% |
| pullback_deep | +15.0% | -36.9% | +42.0% | -24.9% |
| momentum | -10.5% | -22.7% | +5.7% | -17.3% |
| random（10回平均） | +4.7% | -13.8% | +3.0% | -1.1% |

- **採用**: 押し目ルール＋地合いフィルター（60日線の上にある銘柄が50%未満の日は買わない）。儲けを増やすのではなく、悪い日の損失を減らす効果（最大DDが半減、後半の損失が縮小）。前半の利益も減る。
- **候補への反映**: 「高値更新＋出来高増」は候補から外した（総リターンがランダムの幅を下回り、フィルターでも改善せず）。地合いが弱い日は候補を空にせず、依頼文に警告を載せてAIに判断させる（GPT・Claudeに同一の文面）。
- **限界**: 約1年・1つの相場だけ、現在のTOPIX500（生存者バイアス）、6案から選ぶ偏りがある。数か月の仮想売買の結果で再検証する。

## ルール（固定）

| 項目 | 設定 |
| --- | --- |
| 約定 | 判断日の**翌営業日の始値** + スリッページ（既定0.1%）、手数料（既定0.1%）は仮定値 |
| 1銘柄の配分 | 総資産の20%以下 |
| 1回の想定損失 | 総資産の0.5%以下（`stop_price`未指定なら5%下を仮定） |
| 1日の新規購入 | 総資産の20%以下 |
| 空売り・信用 | 禁止 |
| 異常 | JSON不正・銘柄不一致・価格0・資金不足は見送り |
| 重複 | 同じ注文ID（モデル\|判断日\|銘柄\|売買）は二重約定しない |

## 制約と既知の問題

- **1株単位の仮想約定**。日本株は通常100株単位のため、実際の楽天証券の注文方式とは異なる。
- 取得元のYahoo Financeは非公式で、データの正確性・継続性は保証されない。重要な判断には使わない。
- 株式分割はYahoo側の調整済み価格（配当は未調整）を使う。過去分は分割のたびに再取得しないとDBとずれる。
- 祝日は新しい行が増えないだけで、特別な処理はしていない。
- 取引回数が少ないうちの勝率・損益は偶然の影響が大きい。
- 取引履歴はSQLiteの `trades` / `rejections` / `equity_daily` に追記専用で記録（毎日の自動更新ジョブが実行）。注文IDが主キーで、記録済みの約定は書き換わらず二重登録もされない。画面は毎回再計算し、記録と食い違えば「口座詳細」タブに警告を出す（ルールやデータが後から変わった場合の検知）。
- baselineは約490銘柄で売買するため、リスク制限による拒否が多数記録される（仕様）。
- Git未導入のためバージョン管理は未開始。
